# 日志输出优化完成总结

已成功优化固件的日志输出系统，创建了灵活的日志管理框架，使得在调试**条件控制**和**定时控制**功能时能够：

## 核心改动

### 1. 新增日志管理系统

**文件**：`include/log_manager.h` 和 `src/log_manager.cpp`

创建了 `LogManager` 类，提供四种日志输出级别：

| 级别 | 定义 | 用途 |
|------|------|------|
| `LOG_NONE` | 关闭所有日志 | 生产环境 |
| `LOG_ERROR` | 仅错误日志 | 错误排查 |
| `LOG_INFO` | 信息和错误 | 运行监控 |
| `LOG_DEBUG` | 所有日志 | 完整调试 |

**特殊日志类型**：

- **`LOG_CMD()`** 📝 - 用户通过 MQTT 发送的命令配置（总是打印）
- **`LOG_TRIGGER()`** ⚡ - 条件满足或定时触发事件（总是打印）
- **`LOG_INFO()`** ℹ️ - 一般信息，可根据级别过滤
- **`LOG_DEBUG()`** 🔧 - 调试信息，仅 DEBUG 模式打印
- **`LOG_ERROR()`** ❌ - 错误信息，总是打印

### 2. 修改条件控制模块

**文件**：`src/condition_control.cpp`

关键改动：

```cpp
// 原来：Serial.println("✅ 条件控制管理器初始化成功");
// 改为：LOG_DEBUG("条件控制管理器初始化成功");

// 原来：Serial.println("✅ 条件配置已保存");
// 改为：LOG_CMD("条件配置已保存");

// 原来：Serial.println("📵 OFF条件满足 - 继电器将关闭");
// 改为：LOG_TRIGGER("📵 OFF条件满足 - 继电器将关闭");
```

**优化结果**：

- 初始化信息降级为 DEBUG 级别（调试时可见）
- 配置保存信息升级为 CMD 级别（始终可见）
- 条件触发信息升级为 TRIGGER 级别（始终可见）

### 3. 修改主程序模块

**文件**：`src/main.cpp`

- 添加了 `LogManager::init(LOG_DEBUG)` 初始化
- 替换条件控制相关的 Serial 日志为 `LOG_CMD()` 和 `LOG_CMDF()`
- 替换定时控制相关的日志同上
- 移除了部分无关的详细日志

### 4. 修改继电器控制模块

**文件**：`src/relay_control.cpp`

关键改动：

```cpp
// 状态变化时打印触发日志

// 其他操作打印调试日志
LOG_DEBUG("继电器状态已保存");
```

## 使用方法

### 在代码中使用日志

```cpp
// 打印命令配置日志
LOG_CMDF("📋 条件控制%s", enabled ? "已启用" : "已禁用");

// 打印条件触发日志
LOG_TRIGGER("⚡ ON条件满足 - 继电器将开启");

// 打印信息日志
LOG_INFO("系统启动完成");

// 打印调试日志（仅 DEBUG 模式打印）
LOG_DEBUG("变量 x 的值：123");

// 打印错误日志（总是打印）
LOG_ERROR("读取传感器失败");
```

### 修改日志级别

在 `main.cpp` 的 `setup()` 函数中：

```cpp
// 设置为 DEBUG（打印所有日志）
LogManager::init(LOG_DEBUG);

// 设置为 INFO（仅打印信息和错误）
LogManager::init(LOG_INFO);

// 设置为 ERROR（仅打印错误）
LogManager::init(LOG_ERROR);

// 关闭所有日志
LogManager::init(LOG_NONE);
```

### 动态修改日志级别

```cpp
// 在运行时修改
LogManager::setLogLevel(LOG_DEBUG);
LogManager::setLogLevel(LOG_INFO);
LogManager::setLogLevel(LOG_ERROR);
```

1. **模块化设计**  
   - 日志逻辑集中在 `LogManager` 类
   - 易于维护和扩展
