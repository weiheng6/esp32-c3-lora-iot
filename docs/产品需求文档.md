## 1. 产品概述

### 1.1 产品定义

ESP32-C3 LoRa 条件控制边缘设备是一个智能传感和控制设备，具备以下核心能力：
- 🌡️ **实时传感**：采集温湿度数据（通过 SHT31 传感器）
- 🌐 **网络连接**：支持 WiFi 和 MQTT，可上报数据到云平台
- 📡 **LoRa 通信**：支持 433MHz LoRa 协议，可与其他设备通信
- 🔌 **设备控制**：通过继电器控制外部设备（开/关）
- 🧠 **条件控制**：基于温湿度条件自动控制继电器状态
- ⚙️ **配置管理**：支持远程配置和本地配置

### 1.2 应用场景

1. **温室大棚控制**：根据温湿度条件自动控制风扇、加热器等
2. **冷链监测**：实时监测仓库温度，超限自动报警
3. **工业设备监控**：监测生产设备运行状态，条件触发控制
4. **智能家居网关**：作为 LoRa 到 MQTT 的边缘网关，转发消息

## 3. 功能需求

### 3.1 传感器采集功能

#### 3.1.1 温度采集
- **传感器**: Adafruit SHT31 (I2C 地址 0x44)
- **测量范围**: -40 到 +125°C
- **精度**: ±0.2°C
- **采集间隔**: 默认 30 秒，支持动态调整（范围：5-3600 秒）
- **读取方式**: 非阻塞式（20ms 超时保护）
- **缓存机制**: 失败时使用上次成功的值

#### 3.1.2 湿度采集
- **测量范围**: 0 到 100% RH
- **精度**: ±2% RH
- **采集间隔**: 同温度（30 秒）
- **读取方式**: 同温度（20ms 超时保护）
- **缓存机制**: 失败时使用上次成功的值

#### 3.1.3 I2C 通信优化
- **时钟频率**: 400 kHz（快速模式，而非默认 100 kHz）
- **超时保护**: 单次 I2C 读取超过 50ms 时立即返回，使用缓存值
- **自动复位**: 每 5 分钟检查一次 I2C 总线，若检测到 >100 个慢循环则执行完全复位
- **成功率统计**: 跟踪 I2C 读取成功率，目标 >99%

**说明**: 之前 I2C 读取导致 main loop 阻塞（106ms），现已优化到 24-25ms，确保 WiFi 看门狗不超时。

### 3.2 MQTT 通信功能

#### 3.2.1 MQTT 连接

| 参数 | 值 |
|------|-----|
| **Broker 地址** | iot.kebaidata.com |
| **Broker 端口** | 1883 |
| **用户名** | kbuser |
| **密码** | kbuserspasswd |
| **连接方式** | TCP 非加密 |
| **遗嘱消息** | "offline" (QoS=1, Retain=true) |

#### 3.2.2 MQTT 主题定义

所有主题均采用格式: `esp32/{DEVICE_ID}/*`

| 主题 | 方向 | 内容 | 说明 |
|------|------|------|------|
| `esp32/{DEVICE_ID}/temperature` | 上行 | JSON | 温度数据 |
| `esp32/{DEVICE_ID}/humidity` | 上行 | JSON | 湿度数据 |
| `esp32/{DEVICE_ID}/relay` | 上行 | JSON | 继电器状态 |
| `esp32/{DEVICE_ID}/command` | 下行 | JSON | 下行指令 |
| `esp32/{DEVICE_ID}/response` | 上行 | JSON | 命令响应 |
| `esp32/{DEVICE_ID}/status` | 上行 | "online"/"offline" | 设备在线状态 |
| `esp32/{DEVICE_ID}/system/memory` | 上行 | JSON | 内存使用情况 |
| `esp32/{DEVICE_ID}/system/restart` | 上行 | "1" (Retain) | 重启通知 |

**注意**: `{DEVICE_ID}` 是 12 位的 MAC 地址（不含冒号），例如 `8856A66E4924`

#### 3.2.3 数据消息格式

**温度消息** (`esp32/{DEVICE_ID}/temperature`):
```json
{
  "temperature": 24.5,
  "unit": "°C",
  "timestamp": 1626748800
}
```

**湿度消息** (`esp32/{DEVICE_ID}/humidity`):
```json
{
  "humidity": 65.3,
  "unit": "%RH",
  "timestamp": 1626748800
}
```

**继电器状态** (`esp32/{DEVICE_ID}/relay`):
```json
{
  "relay": 1,
  "timestamp": 1626748800
}
```

**内存信息** (`esp32/{DEVICE_ID}/system/memory`):
```json
{
  "available": 220944,
  "usage_percent": 24.3,
  "warning_threshold": 15360,
  "timestamp": 1626748800
}
```

#### 3.2.4 上报间隔

| 数据类型 | 默认间隔 | 最小间隔 | 最大间隔 |
|---------|---------|---------|---------|
| 温度/湿度 | 30 秒 | 5 秒 | 3600 秒 |
| 继电器状态 | 30 秒（与采集间隔同步） | - | - |
| 内存信息 | 30 秒 | - | - |
| 系统诊断 | 30 秒 | - | - |

### 3.4 LoRa 通信功能

#### 3.4.1 LoRa 消息格式

**格式**: `TYPE,TARGET_DEVICE_ID,PAYLOAD`

**消息类型**:

| 类型 | 值 | 说明 |
|------|-----|------|
| 数据消息 | 3 | 转发的传感器数据 |
| 命令消息 | 4 | 转发的下行命令 |
| 心跳消息 | 2 | 定期心跳包 |
| 发现消息 | 1 | 节点发现 |

**示例**:

转发的温湿度数据:
```
3,device-002,{"temp":24.5,"hum":65.3}
```

转发的继电器命令:
```
4,device-003,{"relay":1}
```

#### 3.4.2 LoRa 消息队列

| 参数 | 值 |
|------|-----|
| **队列大小** | 10 条消息 |
| **优先级** | 高(H)/中(M)/低(L) |
| **溢出处理** | 丢弃最低优先级消息 |

**优先级分配**:
- **高(H)**: 继电器控制命令、系统重启通知
- **中(M)**: 传感器数据转发、普通指令
- **低(L)**: 心跳包、发现消息

#### 3.4.3 LoRa 到 MQTT 的转发规则

| 转发方向 | 触发条件 | 操作 |
|---------|---------|------|
| MQTT → LoRa | 收到 MQTT 命令，目标设备不是本机 | 将指令转换为 LoRa 格式并广播 |
| LoRa → MQTT | 收到 LoRa 消息，目标设备是本机 | 将消息解析并上报到对应的 MQTT 主题 |

### 3.6 条件控制功能（高级功能）

#### 3.6.1 基本条件控制

支持基于温湿度阈值的自动控制：

**配置项**:
- **温度条件**: 启用/禁用、阈值（°C）、比较操作符
- **湿度条件**: 启用/禁用、阈值（%RH）、比较操作符
- **逻辑关系**: AND（全部满足） 或 OR（任一满足）
- **滞回控制**: 防止触发频繁抖动

#### 3.6.2 比较操作符

| 操作符值 | 操作符 | 说明 |
|---------|-------|------|
| 0 | < | 小于 |
| 1 | > | 大于 |
| 2 | == | 等于 |

#### 3.6.3 典型配置示例

**场景 1: 温度过高时启动风扇**
```json
{
  "condition": {
    "enabled": true,
    "temp": {
      "enabled": true,
      "threshold": 30.0,
      "compare": 1
    }
  }
}
```
当 `温度 > 30°C` 时，继电器打开

**场景 2: 湿度范围控制（滞回模式）**
```json
{
  "condition": {
    "enabled": true,
    "use_hysteresis": true,
    "humi": {
      "enabled": true,
      "low_threshold": 40.0,
      "high_threshold": 60.0
    }
  }
}
```
- 湿度 > 60% 时，继电器打开
- 湿度 < 40% 时，继电器关闭
- 40-60% 之间保持当前状态（防抖动）

**场景 3: 温湿度同时控制**
```json
{
  "condition": {
    "enabled": true,
    "use_hysteresis": false,
    "temp": {
      "enabled": true,
      "threshold": 25.0,
      "compare": 1
    },
    "humi": {
      "enabled": true,
      "threshold": 70.0,
      "compare": 1
    },
    "logic": "and"
  }
}
```
当 `温度 > 25°C 且 湿度 > 70%` 时，继电器打开

### 3.7 WiFi 与网络管理

#### 3.7.1 WiFi 连接模式

**正常模式** (STA - 站点模式):
- 连接到现有 WiFi 网络
- 获取 IP 地址后连接 MQTT

**AP 模式** (热点模式):
- 创建自己的 WiFi 热点用于配置
- SSID: "Scott_Device"
- 密码: "88888888"
- 用户可通过浏览器 (http://192.168.4.1) 配置 WiFi

**自动切换逻辑**:
1. 启动时尝试连接已保存的 WiFi
2. 连接失败 → 自动进入 AP 模式
3. 用户配置新 WiFi → 设备自动重启
4. 重启后再次尝试连接新 WiFi

## 4. 数据存储 (Preferences/NVS Flash)

### 4.2 数据持久化策略

- **即时保存**: 关键配置变更时立即保存到 Preferences
- **启动加载**: 设备启动时自动加载所有配置
- **保留历史**: 配置被删除前保留最后的有效值
- **容错机制**: 配置加载失败时使用默认值

## 9. 安全与可靠性

### 9.1 数据安全

- ✅ WiFi 密码存储在 Preferences（掉电保存）
- ✅ MQTT 密码硬编码在代码中（无 OTA 风险）
- ❌ MQTT 连接非加密（TCP，未来改进）
- ⚠️ LoRa 通信无加密（物理隔离的本地网络）

### 9.2 设备保护

- ✅ 看门狗超时自动重启
- ✅ 内存不足自动重启
- ✅ I2C 故障自动复位
- ✅ WiFi 断连自动重连
- ✅ MQTT 断连自动重连

- ✅ JSON 解析失败不会崩溃
- ✅ 无效的 MQTT 消息直接丢弃
