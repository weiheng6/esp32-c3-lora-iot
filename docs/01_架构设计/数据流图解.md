# 数据流图解

## 1. 完整的端到端数据流

```
物理世界
    │
    ├─ 温度 (°C)
    ├─ 湿度 (%RH)
    └─ GPIO 继电器控制信号
         │
         ▼
     [硬件接口]
         │
    ┌────┴────┐
    │          │
    ▼          ▼
[I2C 读]  [GPIO 输出]
SHT31     继电器
    │
    ▼
[SensorManager]
  readBoth()
    │
    ├─ 超时检查 (50ms)
    ├─ 缓存机制
    └─ 统计信息
         │
         ▼
[本地变量]
temperature
humidity
         │
         ▼
[采集队列]
每 30s 采集一次
         │
         ▼
┌───────────────┬──────────────┐
│               │              │
▼               ▼              ▼
[本地存储]   [MQTT]        [LoRa]
Preferences  上报         中继/转发
│                           │
├─ deviceId        ├─ msg to device-002
├─ relay_state     ├─ msg to device-003
├─ config          └─ msg to device-004
│                           │
▼                           ▼
[内存 NVS]              [RF 433MHz]
 (Flash)                物理空间
 │
 └─ 掉电保存
```

## 2. 典型工作流：30秒采集周期

```
时刻 t=0s          时刻 t=30s         时刻 t=60s
   │                  │                 │
   ├─ 等待 ...        ├─ 等待 ...       ├─ 等待 ...
   │  (29s)           │  (29s)          │  (29s)
   │                  │                 │
   ├─ 采集传感器 ─────┤ 采集传感器 ─────┤ 采集传感器
   │ I2C read     │ I2C read     │ I2C read
   │ ~40ms       │ ~40ms       │ ~40ms
   │                  │                 │
   ├─ 打包 JSON       ├─ 打包 JSON       ├─ 打包 JSON
   │                  │                 │
   ├─ MQTT 发送       ├─ MQTT 发送       ├─ MQTT 发送
   │ TLS ~45ms    │ TLS ~45ms    │ TLS ~45ms
   │                  │                 │
   ├─ 云端存储        ├─ 云端存储        ├─ 云端存储
   │                  │                 │
   └─ 等待下次 ───────┴──────────────────┴─ 等待下次
```

## 3. I2C 读取细节

```
主 MCU (ESP32-C3)          从设备 (SHT31)
    │                           │
    │ 1. START                   │
    ├──────────────────────────>│
    │ 2. Write Address (0x44)    │
    ├──────────────────────────>│
    │ 3. Wait (内部转换)          │
    │                           │ ~30-40ms 内部处理
    │ 4. Read Data              │
    ├──────────────────────────>│
    │<─ 6 bytes (T + CRC + H + CRC)─┤
    │ 5. STOP                   │
    ├──────────────────────────>│
    │                           │
    ▼ 完成（总耗时 40ms）         ▼
```

**关键点**:
- SHT31 的测量时间约 30-40ms（取决于精度和供电）
- I2C 通信本身 <5ms，主要时间在传感器内部转换
- 我们的超时保护设在 50ms，允许正常操作完成

## 4. MQTT 消息流

### 4.1 正常上报流程

```
设备侧                         MQTT Broker
    │
    ├─ 打包 JSON
    │  {temp: 24.5, hum: 65.3}
    │
    ├─ 创建 TLS 连接
    │  (如果已连接则复用)
    │
    ├─ 发布到主题
    │  /home/device-001/sensor
    │
    ├─────── PUBLISH ────────────────>│
    │<────── PUBACK ─────────────────┤ (QoS 0 时无 ACK)
    │
    ├─ 记录统计
    │  lastMqttPublishTime
    │  mqttPublishCount++
    │
    └─ 等待下次采集

    [总耗时: 45-50ms]
```

### 4.2 命令下发流程（MQTT → 设备）

```
云端 / 用户                  MQTT Broker        设备侧
    │                            │                 │
    │ 发送命令                    │                 │
    │ {type: set_relay, ...}      │                 │
    │                             │                 │
    └────── PUBLISH ─────────────>│                 │
                                 │                 │
                                 │ 根据订阅转发    │
                                 ├────── DELIVER ─>│
                                 │                 │
                                 │           [mqttCallback]
                                 │           ├─ 解析 JSON
                                 │           ├─ 检查目标 ID
                                 │           │
                                 │           ├─ 若是本设备
                                 │           │  └─ 执行命令
                                 │           │     • 控制继电器
                                 │           │     • 修改参数
                                 │           │     • 存储到 NVS
                                 │           │
                                 │           └─ 若是其他设备
                                 │              └─ 转发为 LoRa
                                 │
                                 │  发送应答
                    [应答消息]    │<────── PUBLISH ─
                                 │
    [总耗时: 50-100ms 取决于转发]
```

## 5. LoRa 消息流

### 5.1 接收流程

```
RF 信号 (433MHz)          RFM95W 模块        ESP32-C3 MCU
    │                           │                 │
    │ 电磁波                    │                 │
    ├──────────────────────>│                 │
    │                       │ 解调+解码      │
    │                       │                 │
    │                   [ISR 触发]           │
    │                       ├────────────────>│
    │                       │          [LoRa ISR]
    │                       │          ├─ 读取 FIFO
    │                       │          ├─ 提取消息
    │                       │          ├─ 放入队列
    │                       │          │  (优先级排序)
    │                       │          └─ 返回
    │                       │                 │
    │                   [等待下一条]         │ 继续主循环
    │                       │                 │
    │                       │         [定期处理队列]
    │                       │         ├─ 取出消息
    │                       │         ├─ 解析目标
    │                       │         ├─ 若是本设备
    │                       │         │  └─ 执行
    │                       │         └─ 若是其他
    │                       │            └─ 转发到 MQTT
    │                       │                 │
    └───────────────────────┴─────────────────┘
```

### 5.2 转发规则

```
消息来源
    │
    ├─ MQTT 下行命令
    │  └─ targetId != 本设备ID
    │     └─ 转换格式后发送 LoRa
    │
    └─ LoRa 接收
       └─ targetId != 本设备ID
          └─ 转发回 MQTT
```

**示例**:
```
场景 1: MQTT 命令转 LoRa
云端: /home/device-001/cmd <- {target: device-003, relay: 1}
转换为: TYPE,device-003,relay=1
LoRa 广播到 433MHz
device-003 收到后自动执行

场景 2: LoRa 消息转 MQTT
device-002 发送: DATA,device-001,24.5,65.3
device-001 接收后
转发为: /home/device-002/sensor <- {temperature: 24.5, humidity: 65.3}
```

## 6. 内存数据流

### 6.1 栈（Stack）

```
┌─────────────────────────────┐
│    [main loop 局部变量]      │ <- 递减增长
│    - step1Start, duration   │
│    - temp, humidity         │
│    - jsonBuffer             │
│    - mqttPayload            │
└─────────────────────────────┘
         ↑ 栈指针
         │
   [堆 (Heap)]
         │
┌─────────────────────────────┐
│                             │ <- 递增增长
│    [动态分配的对象]          │
│    - PubSubClient 缓冲      │
│    - LoRa 库内部缓冲        │
│    - WiFi 栈缓冲            │
└─────────────────────────────┘
```

### 6.2 全局数据（静态存储）

```
全局变量 (在 setup 前初始化)

float lastTemp = 20.0;          ← 传感器缓存
float lastHumidity = 50.0;      ← 传感器缓存
unsigned long lastSuccessfulRead;
uint32_t i2cReadAttempts;
uint32_t i2cReadSuccesses;

uint32_t loopSlowCount;         ← 诊断计数
unsigned long lastLoopDuration;

WiFiClient espClient;           ← MQTT 客户端
PubSubClient mqttClient(espClient);

RFM95 lora = RFM95(LORA_CS);   ← LoRa 驱动
```

### 6.3 Flash 存储（NVS Preferences）

```
NVS 分区 (永久存储)
│
├─ sensor_config 命名空间
│  ├─ device_id = "device-001"
│  ├─ acquisition_interval = 30000
│  └─ relay_state = 0
│
└─ mqtt_config 命名空间
   ├─ mqtt_server = "broker.example.com"
   ├─ mqtt_port = 1883
   └─ mqtt_user = "user"
```

## 7. 时间轴（关键操作的耗时）

```
0ms    ┌─ 采集传感器
       │  I2C readBoth()
       │
40ms   ├─ I2C 完成
       │  ┌─ 解析并打包 JSON (< 5ms)
       │  │
45ms   ├─ JSON 完成
       │  ┌─ MQTT TLS 连接 (10ms，已连接则 0ms)
       │  │
55ms   ├─ MQTT 发送完成
       │  ┌─ 处理消息队列
       │  │
70ms   ├─ 所有 I/O 完成
       │  ┌─ 等待下一个 100ms
       │  │
100ms  ├─ loop() 结束，yield() 释放 CPU
       │  ┌─ WiFi 任务获得执行时间（~400ms 周期）
       │  │
       └─ 继续循环
```

## 8. 错误恢复流程

### 8.1 I2C 读取失败

```
readBoth() 超时
    │
    ├─ 检测 (耗时 > 50ms)
    │
    ├─ 使用缓存值
    │  lastTemp, lastHumidity
    │
    ├─ 返回 false (表示失败)
    │
    ├─ 不阻塞 loop
    │
    └─ 下次 30s 重试
       └─ 如果再次失败
          └─ 定期重置 I2C 总线
```

### 8.2 MQTT 连接失败

```
mqttClient.connect() 失败
    │
    ├─ failureCount++
    │
    ├─ if failureCount > 3
    │  └─ 指数退避重连
    │     1s, 2s, 4s, 8s ...
    │
    ├─ WiFi 断连重新连接
    │
    └─ 继续本地运行
       └─ 传感器数据存储在内存
          等待恢复后上报
```

### 8.3 内存不足

```
availableMemory < 15KB
    │
    ├─ 打印警告
    │  "⚠️ 内存警告! 可用仅 10KB"
    │
    ├─ 触发重启
    │  ESP.restart()
    │
    └─ 重启后自动恢复
       └─ 所有配置从 NVS 恢复
```
