## 2. 硬件规格

| 组件 | 规格 | 用途 |
|------|------|------|
| **MCU** | ESP32-C3 (Adafruit QtPy) | 主控芯片：160MHz RISC-V32, 320KB SRAM, 4MB Flash |
| **传感器** | Adafruit SHT31 | I2C 温湿度传感器（0-100% RH, -40 to +125°C） |
| **LoRa** | RFM95W 模块 | 433MHz/915MHz（默认配置中的频段） |
| **WiFi** | 内置 802.11 b/g/n | 2.4GHz，用于 MQTT 上报 |
| **继电器** | GPIO 继电器（5V） | GPIO 输出控制（可配置） |
| **时钟** | 内置晶振 40MHz | 实时时钟、时间戳 |

## 4. 数据流概览

### 场景 1：传感器 → 本地存储 → MQTT

```
SHT31 温湿度传感器
    ↓ (I2C, <50ms)
SensorManager.readBoth()
    ↓ (缓存到内存)
acquireSensorData() 
    ↓ (采集间隔: 30s)
MQTT 发布 (mqttPublish)
    ↓ (TLS, ~45ms)
MQTT Broker (云端)
```

### 场景 2：MQTT 命令 → 本设备控制

```
MQTT Broker (云端)
    ↓ (订阅 /device/{deviceId}/cmd)
mqttCallback() 中断回调
    ↓ (解析 JSON 命令)
检查目标设备 ID
    ├─ 本设备 → 执行命令（控制继电器、调整参数）
    └─ 其他设备 → 转发为 LoRa 消息
```

### 场景 3：LoRa 消息 → 转发

```
LoRa 接收 (射频)
    ↓ (ISR 中断)
将消息放入队列
    ↓ (优先级排序)
定期处理队列
    ├─ 若目标是本设备 → 执行
    └─ 若目标是其他 → 转发到 MQTT
```

## 5. 关键指标与限制

### 时间约束

| 指标 | 目标值 | 当前值 | 说明 |
|-----|-------|-------|------|
| **Loop 周期** | <30ms | 20-25ms | 保证 WiFi 看门狗有时间处理 |
| **I2C 读取** | <50ms | 39-40ms | SHT31 正常响应时间 |
| **MQTT 发送** | <50ms | 45-50ms | TLS 握手开销 |
| **WiFi 看门狗** | 5s | 5s | 超时触发重启 |

### 内存约束

| 资源 | 总量 | 使用 | 可用 |
|-----|------|------|------|
| **SRAM** | 320 KB | 41 KB | 279 KB |
| **Flash** | 4 MB | 822 KB | 3.2 MB |
| **安全门槛** | 15 KB | - | 当可用 <15KB 时重启 |

### 队列与缓冲

| 队列/缓冲 | 大小 | 说明 |
|---------|------|------|
| **LoRa 消息队列** | 10 条 | 优先级 FIFO，容满则丢弃 |
| **JSON 缓冲** | 200 字节 | MQTT 命令解析 |
| **MQTT Payload** | 500 字节 | 单条消息限制 |

## 6. 核心工作流程

### 6.1 设备启动流程

```
1. setup() 阶段 (执行一次)
   ├─ Serial.begin() - 日志系统
   ├─ sensorManager.begin() - SHT31 初始化
   ├─ WiFi.begin() - 连接 WiFi
   ├─ mqttClient.connect() - 连接 MQTT
   ├─ LoRa.begin() - 初始化 LoRa
   └─ attachInterrupt() - 配置 LoRa 中断

2. loop() 主循环 (持续执行)
   │
   ├─ 每 30s 采集一次传感器
   ├─ 每秒检查 WiFi/MQTT 连接状态
   ├─ 处理 LoRa 消息队列
   ├─ 处理 MQTT 下行命令
   ├─ 执行条件控制逻辑
   ├─ 定期打印诊断信息
   └─ delay(100ms) 释放 CPU 时间
```

### 6.2 I2C 读取流程（关键优化点）

```
readBoth(temperature, humidity)
│
├─ 检查超时计数器
│  └─ if (readTime > 50ms) 使用缓存值 return false
│
├─ 尝试读取温度
│  └─ temperature = sht31.readTemperature()
│
├─ 检查第一阶段是否超时
│  └─ if (tempTime > 50ms) return false (使用缓存)
│
├─ 读取湿度
│  └─ humidity = sht31.readHumidity()
│
├─ 测量总耗时
│  └─ readDuration = millis() - start
│
├─ 数据有效性检查
│  ├─ if (isnan(temp) || isnan(hum)) return false
│  └─ else 更新缓存，返回 true
│
└─ 统计信息
   └─ i2cReadAttempts++, i2cReadSuccesses++
```

## 7. 持久化存储 (Preferences)

项目使用 ESP32 的 `Preferences` (NVS Flash) 存储配置，不依赖 EEPROM：

| 键名 | 类型 | 说明 |
|------|------|------|
| `device_id` | String | 本设备唯一标识 |
| `mqtt_server` | String | MQTT 服务器地址 |
| `mqtt_port` | uint16_t | MQTT 服务器端口 |
| `acquisition_interval` | uint32_t | 传感器采集间隔（毫秒） |
| `relay_state` | uint8_t | 继电器状态（0/1） |
| `condition_enabled` | uint8_t | 条件控制是否启用 |

## 8. 通信协议定义

### 8.1 MQTT 消息格式

**上行（设备 → 云）**:
```json
{
  "deviceId": "device-001",
  "timestamp": 1626748800,
  "temperature": 24.5,
  "humidity": 65.3,
  "relay_state": 1,
  "signal_strength": -75,
  "uptime_seconds": 3600
}
```

**下行（云 → 设备）**:
```json
{
  "type": "set_params",
  "targetDeviceId": "device-001",
  "params": {
    "acquisition_interval": 30000,
    "relay_control": 1
  }
}
```

### 8.2 LoRa 消息格式

```
格式: TYPE,DEVICE_ID,PAYLOAD

示例:
  - DATA,device-002,24.5,65.3  (转发的传感器数据)
  - CMD,device-003,relay=1     (转发的控制命令)
  - PING,device-004,ok         (心跳消息)
```

## 9. 错误处理与恢复机制

| 错误类型 | 检测方式 | 恢复机制 |
|---------|---------|---------|
| **I2C 超时** | 读取耗时 > 50ms | 使用缓存值，不阻塞 loop |
| **WiFi 断连** | `!WiFi.isConnected()` | 自动重连（exponential backoff） |
| **MQTT 断连** | `!mqttClient.connected()` | 自动重连，最多 5 次 |
| **LoRa 队列满** | 队列大小 == 10 | 丢弃优先级最低的消息 |
| **内存紧张** | 可用 <15KB | 主动重启设备 |
| **看门狗超时** | Loop > 5s 不执行 | 自动重启 |

## 10. 架构设计思想

1. **模块化**: 传感器、网络、LoRa 分离，便于独立测试
2. **鲁棒性**: 所有 I/O 操作都有超时保护和备用值
3. **低延迟**: Loop 周期控制在 20-30ms，不会阻塞 WiFi 任务
4. **高可靠性**: 多重冗余（缓存、重连、诊断），确保长期稳定运行
5. **可配置性**: 采集间隔、MQTT 参数、LoRa 频段均可动态调整
