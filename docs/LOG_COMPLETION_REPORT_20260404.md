## 📋 工作总结

### 问题陈述

在调试条件控制和定时控制功能时，日志输出混乱，关键信息（设置命令、条件触发）被大量无关日志淹没，影响调试效率。

### 解决方案

实现了灵活的日志管理系统，支持：
- **4 个日志级别**：DEBUG、INFO、ERROR、NONE
- **2 个特殊日志类型**：CMD（命令）、TRIGGER（触发）
- **动态日志级别调整**，无需重新编译
- **简洁的 API**，通过宏简化调用

## 💻 使用方法

### 基本使用

```cpp
#include "log_manager.h"

void setup() {
  Serial.begin(115200);
  LogManager::init(LOG_DEBUG);  // 初始化日志系统
}

void loop() {
  LOG_CMDF("📋 设置命令：%s", cmd);      // 命令日志
  LOG_TRIGGER("⚡ 条件满足");             // 触发日志
  LOG_INFOF("ℹ️ 信息：%d", value);       // 信息日志
  LOG_DEBUGF("🔧 调试：%d", debug_val);  // 调试日志
  LOG_ERROR("❌ 错误信息");               // 错误日志
}
```

### 动态调整日志级别

```cpp
// 在任何地方调用以改变日志级别
LogManager::setLogLevel(LOG_DEBUG);  // 切换为调试模式
LogManager::setLogLevel(LOG_INFO);   // 切换为信息模式
LogManager::setLogLevel(LOG_ERROR);  // 切换为错误模式
LogManager::setLogLevel(LOG_NONE);   // 关闭日志
```

使用你的 MQTT 客户端向 `iot/esp32/8856A66E4924/cmd` 发送命令。

**示例**：
```json
{
  "condition": {
    "enabled": true,
    "temp": {
      "enabled": true,
      "high_threshold": 30.0,
      "low_threshold": 25.0

    "use_hysteresis": true
  }
}
```

