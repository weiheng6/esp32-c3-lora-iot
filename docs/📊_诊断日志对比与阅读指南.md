## 诊断日志的阅读方法

### 场景 1：看到这样的日志

```
🌐 网络状态诊断:
   WiFi: ✅ 已连接 (RSSI: -48 dBm, 状态码: 3)
   MQTT: ❌ 未连接
   综合: ⚠️  网络不可用

⚠️  网络连接不可用（WiFi:✅, MQTT:❌）
   → MQTT 未连接，需要重新连接
```

**判断：** 
- WiFi 连接良好（RSSI -48 dBm 是强信号）
- MQTT 没有连接（原因待查）
- **问题根源：** MQTT 连接失败

**解决步骤：**
1. 检查 MQTT 服务器是否在线
2. 检查 MQTT 配置（服务器地址、端口、凭证）
3. 检查防火墙是否阻止了 MQTT 端口
4. 等待自动重连（通常几秒后会重连）

## 💡 实用技巧

### Tip 1：快速定位问题

看到 "网络连接不可用" 时，直接查看前一条 "网络状态诊断"：
- 如果 `WiFi: ❌` → **WiFi 问题**（检查 SSID、密码、信号强度）
- 如果 `MQTT: ❌` → **MQTT 问题**（检查服务器、凭证、防火墙）
- 如果都 `❌` → **完全离线**（检查网络连接）
- 如果都 `✅` 但网络不可用 → **稀有情况**（可能是 Bug，请保存日志）

### Tip 2：监控信号强度

观察 `RSSI` 值：
- `-30 dBm` - 非常强的信号（距离 AP 很近）
- `-48 dBm` - 很好的信号（正常使用范围）
- `-70 dBm` - 弱信号（在自动跳过上报的阈值）
- `-80 dBm` - 非常弱的信号（可能连接不稳定）

如果看到 RSSI 值越来越小（比如 -48 → -68 → -75），说明信号在恶化，可能要移近 AP

### Tip 3：追踪网络稳定性

运行 8 小时测试时，收集所有的 "网络状态诊断" 输出：
```
第 0-10 分钟：WiFi ✅ MQTT ✅（正常启动）
第 10-30 分钟：WiFi ✅ MQTT ✅（稳定运行）
第 1-2 小时：WiFi ✅ MQTT ✅（持续稳定）
第 4 小时：WiFi ✅ MQTT ❌（关键时间点出问题？）
第 8 小时：...（记录最终状态）
```

这样可以追踪问题发生的时间点
