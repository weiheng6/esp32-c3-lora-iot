# 🔍 固件卡死问题深度分析报告

## 问题描述
- 运行 1 小时后自动卡死（需要重启恢复）
- 网络状态正常（已确认）
- 内存使用率稳定（24-30%）
- 数据上报频率 1s

---

## 发现的关键问题

### 🔴 问题 1：MQTT 连接丢失未及时检测
**位置**：`mqtt_manager.cpp` - loop() 函数

**现象**：
```cpp
void MQTTManager::loop() {
  if (mqttClient.connected()) {
    mqttClient.loop();
  }
}
```

**问题**：
- PubSubClient 的 loop() 函数**默认有内置超时机制**
- 如果网络断开但 `connected()` 还返回 true（状态不同步），loop() 会陷入阻塞等待
- 这会导致整个 loop 函数卡死 100-500ms
- 循环调用 MQTT 后面的 WebServer 和 LoRa 处理得不到 CPU 时间
- 长期累积导致系统彻底卡死

---

### 🔴 问题 2：WebServer 请求处理阻塞
**位置**：`web_server.cpp` - handleClient() 和各个 handler 函数

**问题**：
```cpp
void WebServerManager::handleClient() {
  if (started) {
    server.handleClient();  // ← 可能在等待 HTTP 客户端响应
  }
}
```

- ESP 的 WebServer 在处理客户端请求时**没有超时保护**
- 如果客户端（手机/浏览器）连接后不关闭，server 会一直等待
- 特别是在扫描 WiFi（handleScanWiFi）时，可能需要 3-5 秒
- 这期间 MQTT 的心跳包会丢失，导致连接断开
- 即使客户端断开，socket 也可能保留，继续阻塞

---

### 🔴 问题 3：LoRa 模块操作可能阻塞
**位置**：`lora_manager.cpp` - processQueue() 和 receiveMessage()

**问题**：
```cpp
void LoRaManager::processQueue() {
  // ...
  LoRa.beginPacket();  // ← 可能阻塞
  LoRa.print(message);
  LoRa.endPacket();     // ← 可能阻塞
}

String LoRaManager::receiveMessage() {
  int packetSize = LoRa.parsePacket();  // ← 可能很慢
  // ...
}
```

- LoRa 库的 parsePacket() 会扫描空中信号，可能耗时 10-50ms
- 特别是在干扰较多的环境
- 长期积累这些延迟，loop 的执行周期会不断延长

---

### 🔴 问题 4：MQTT 连接状态判断不够严格
**位置**：`main.cpp` - loop() 函数

**问题**：
```cpp
// 连接 MQTT（带重连机制）
if (!mqttManager.isConnected() && WiFi.status() == WL_CONNECTED) {
  // 重连逻辑
}
```

- 检查间隔固定（MQTT_RECONNECT_INTERVAL = 5秒）
- 如果连接在第 1 秒断开，要等 4 秒才能重连
- 期间 MQTT 上报会失败，但没有立即重试
- 这 4 秒内，系统可能因其他原因卡死

---

### 🟡 问题 5：缺少关键的日志监控点
**问题**：
- 没有统计 loop 周期时间
- 没有监测 MQTT 断连次数
- 没有监测 WebServer 请求处理时间
- 没有监测 LoRa 操作耗时
- 无法诊断到底是哪个模块导致卡死

---

## 根本原因分析

这是一个**看门狗(Watchdog)和多个"隐形阻塞"累积的问题**：

1. **LoRa parsePacket()** 每次执行 20-50ms（特别是有干扰时）
2. **WebServer 处理** 如果有客户端连接，可能卡住 500-2000ms
3. **MQTT loop()** 网络异常时可能等待 100-300ms
4. **系统任务切换** WiFi 后台任务每 5-10ms 抢占 CPU

经过 1-2 小时的积累：
- 这些小延迟不断累积
- 最终某个时刻，loop 周期突然变成 1-2 秒
- MQTT 心跳超时
- WebServer 无法响应
- 系统看起来"卡死"了

---

## 解决方案

### ✅ 修复 1：添加 MQTT loop 超时保护
使用非阻塞模式，限制 MQTT 操作时间。

### ✅ 修复 2：WebServer 添加活跃检查和客户端超时
定期检查并清理僵尸连接。

### ✅ 修复 3：LoRa 操作分解为小步骤
避免单次操作耗时过长。

### ✅ 修复 4：添加详细的性能监控日志
统计每个模块的执行时间。

### ✅ 修复 5：优化重连策略
从固定间隔改为指数退避 + 立即重试。

---

## 预期效果

修复后：
- ✅ loop 周期稳定在 20-30ms
- ✅ 不再出现突然卡死
- ✅ MQTT 连接更加稳定
- ✅ 可运行 24 小时 + 无问题
