# 日志解读指南

## 1. 日志符号速查表

| 符号 | 含义 | 级别 | 常见原因 |
|------|------|------|---------|
| ✅ | 成功/初始化完成 | INFO | 正常操作完成 |
| 🔗 | 连接中 | INFO | 正在建立连接 |
| 🟢 | 连接成功 | INFO | 连接已建立 |
| 🟡 | 警告/降级 | WARN | 可能有问题但继续运行 |
| ⚠️  | 警告（单个） | WARN | 需要注意的异常 |
| ⚠️⚠️ | 警告（双个/严重） | WARN | 更严重的警告 |
| ❌ | 失败/错误 | ERROR | 操作失败 |
| 🔄 | 重置/重新初始化 | INFO | 系统自我恢复 |
| 📊 | 统计/诊断 | INFO | 定期性能数据 |
| 📤 | 发送/上报 | INFO | 数据上行 |
| 🔍 | 采集/本地操作 | DEBUG | 本地数据获取 |
| 💾 | 存储/配置 | DEBUG | NVS 操作 |

## 2. 完整日志解析示例

### 2.1 设备启动日志

```
┌─────────────────────────────────────────────────────────────┐
│                    设备启动过程 (setup)                      │
└─────────────────────────────────────────────────────────────┘

✅ SHT31 传感器初始化成功！
  ├─ 含义: SHT31 在 I2C 地址 0x44 找到并初始化成功
  ├─ 应该看到: ✅ (绿色)
  └─ 如果看到 ⚠️: 传感器未接或接线问题

🔗 连接到 WiFi: MyNetwork
  ├─ 含义: 开始连接 WiFi，显示 SSID
  ├─ 应该看到: 这行之后跟 🟢
  └─ 如果卡住: 可能 WiFi 密码错误或信号太弱

🟢 WiFi 连接成功！
  ├─ 含义: WiFi 已连接，获得 IP 地址
  ├─ 应该看到: 这行之后跟 MQTT 连接日志
  └─ 如果没有: WiFi 可能自动断连

🔌 MQTT 连接成功！
  ├─ 含义: 成功连接到 MQTT Broker
  ├─ 应该看到: 这行之后开始看到数据
  └─ 如果失败: 检查 MQTT_SERVER、端口、用户名密码

🟢 LoRa 初始化完成
  ├─ 含义: LoRa 模块已初始化，射频就绪
  ├─ 应该看到: 此后可以接收 LoRa 消息
  └─ 如果失败: LoRa SPI 接线问题
```

**正常启动应该看到的流程**:
```
✅ → 🔗 → 🟢 → 🔌 → 🟢 → LoRa
(约 1-2 秒)
```

### 2.2 正常运行日志（每 30 秒）

```
🔍 本地采集 - 温度：24.19 °C    湿度：36.82 %RH
  ├─ 含义: I2C 成功读取传感器数据
  ├─ 在你看到: 这行之前已经过了 I2C 超时保护
  ├─ 数据范围: 温度 -40 ~ +125°C，湿度 0 ~ 100%
  └─ 频率: 每 30 秒一次

📤 MQTT 上报 - 温度：24.17 °C   湿度：36.82 %RH
  ├─ 含义: 数据已成功发送到 MQTT Broker
  ├─ 耗时: 通常 40-50ms (TLS 握手)
  ├─ 频率: 与 🔍 相同（每 30 秒）
  └─ 如果没看到: MQTT 连接可能断开
```

**正常周期应该看到**:
```
时刻 0s:   🔍 采集传感器
时刻 0-2s: 📤 MQTT 上报
...
时刻 30s:  🔍 采集传感器（重复）
时刻 30-32s: 📤 MQTT 上报（重复）
```

### 2.3 诊断日志（每 30 秒）

```
📊 定期诊断 - Loop平均耗时: 24 ms
  ├─ 含义: main loop 的平均单次执行时间
  ├─ 目标范围: 20-30ms
  ├─ >50ms: ⚠️ 有问题
  └─ >100ms: ❌ 严重问题

├─ I2C 成功率: 100% (1200/1200)
  ├─ 含义: I2C 读取成功率 = 成功次数 / 总尝试次数
  ├─ 目标: >99%
  ├─ 95-99%: ⚠️ 可能有干扰
  └─ <95%: ❌ I2C 总线故障

├─ MQTT 连接: 成功 (发送: 120, 失败: 0)
  ├─ 含义: MQTT 连接状态和历史记录
  ├─ 发送: 自上次诊断以来的发送次数
  ├─ 失败: 失败的发送次数
  └─ 如果失败 >0: 网络不稳定

├─ LoRa 队列: 0/10 条消息
  ├─ 含义: LoRa 消息队列的当前占用状态
  ├─ 0/10: 队列空（正常）
  ├─ 8-10/10: 队列几乎满（可能网络拥塞）
  └─ 如果经常满: 考虑减少转发频率

├─ 内存: 可用 220KB, 使用率 24.3%
  ├─ 含义: 堆内存使用统计
  ├─ 使用率 <40%: ✅ 正常
  ├─ 40-50%: ⚠️ 注意（可用空间减少）
  ├─ >50%: ❌ 危险（容易 OOM）
  └─ 如果可用 <15KB: 触发重启保护

└─ 运行时间: 1 天 12 小时
  ├─ 含义: 设备连续运行时长（自上次启动）
  ├─ 如果突然重置: 说明发生了重启或掉电
  └─ 目标: 连续运行 7+ 天无重启
```

## 3. 警告日志及解决方案

### 3.1 I2C 相关警告

#### 警告 #1: 大耗时

```
⚠️  I2C 读取耗时较长：45 ms
含义: 单次 I2C 读取接近上限（45-50ms）
原因: 
  ├─ 正常: SHT31 内部转换时间变化
  ├─ 可能: I2C 总线有轻微干扰
  └─ 严重: I2C 总线反复复位
处理: 
  ├─ 单次出现: 无需处理 ✅
  ├─ 频繁出现: 检查电磁干扰，移开强干扰源
  └─ 长期: 考虑降低 I2C 时钟至 100kHz
```

#### 警告 #2: 超时

```
❌ I2C 读取超时...使用缓存值
含义: I2C 读取耗时 >50ms，触发超时保护
原因:
  ├─ 短暂干扰: 一次性问题
  ├─ I2C 总线卡住: 从设备未释放总线
  └─ 硬件故障: 接线断或传感器坏
处理:
  ├─ 次数 <5: 正常，无需处理 ✅
  ├─ 次数 5-20: 观察，可能有干扰
  └─ 次数 >20: 检查接线或重启设备
输出: 数据使用缓存值，不中断上报
```

#### 警告 #3: 总线复位

```
🔄 I2C 总线已复位（第 2 次）
含义: 检测到大量慢循环，执行 I2C 总线完全复位
原因:
  ├─ I2C 总线陷入某种错误状态
  ├─ 从设备未正确响应多次
  └─ 反复出现临时故障
处理:
  ├─ 次数 0-1: ✅ 正常（整个运行期间最多复位 1-2 次）
  ├─ 次数 2-5: ⚠️ 注意，可能有干扰
  └─ 次数 >5: ❌ 严重问题，检查硬件
优点: 复位后通常恢复正常，无需人工干预
```

### 3.2 WiFi 相关警告

```
⚠️  WiFi 连接已断开，正在重新连接...
含义: WiFi 连接丢失
原因:
  ├─ 路由器故障
  ├─ 信号太弱
  ├─ SSID/密码改变
  └─ WiFi 模块故障
检查:
  ├─ 看路由器: 是否还在工作？
  ├─ 看信号强度: 日志中的 RSSI 值 (目标 > -70 dBm)
  ├─ 看MQTT连接: 如果 WiFi 恢复后 MQTT 也恢复，说明正常
  └─ 长期无法恢复: 可能需要重启设备
```

### 3.3 MQTT 相关警告

```
⚠️  MQTT 发布失败，重新连接中...
含义: MQTT 消息发送失败
原因:
  ├─ MQTT Broker 宕机
  ├─ 网络延迟超过超时时间
  ├─ 认证失败（用户名/密码错）
  └─ 消息过大 (>500 字节)
处理:
  ├─ 查看 Broker: ping broker.example.com
  ├─ 查看凭证: 确认用户名密码
  ├─ 查看消息大小: JSON 不要超过 500 字节
  └─ 观察日志: 如果之后恢复 🟢，说明是临时问题
```

### 3.4 内存相关警告

```
⚠️  内存警告! 可用仅 10KB (使用率 97%)
含义: 剩余可用内存已低于 15KB 警告线
原因:
  ├─ 内存泄漏: 某处分配了大量内存未释放
  ├─ 缓冲区溢出: JSON 或网络缓冲太大
  └─ 库的动态分配: WiFi 或 MQTT 库缓冲
处理:
  ├─ 立即: 查看是否有大数组或字符串声明
  ├─ 短期: 重启设备恢复内存
  ├─ 长期: 分析代码中的大对象
  └─ 触发: 可用 <15KB 时设备自动重启保护
```

### 3.5 慢循环警告

```
⚠️  慢循环 #1: 105 ms （I2C失败x0, MQTT失败x0）
含义: 单次 main loop 执行时间 >100ms（超时）
原因:
  ├─ I2C 读取耗时: 40-50ms
  ├─ MQTT 发送耗时: 40-50ms
  ├─ 两者叠加: 80-100ms（接近超时）
  ├─ 其他操作: delay(), Serial 输出等
  └─ WiFi 栈处理: 内部任务执行
处理:
  ├─ 次数 <10: 正常，允许偶发
  ├─ 次数 10-100: ⚠️ 观察，但仍可接受
  ├─ 次数 >100: ❌ 严重，触发 I2C 总线复位
  └─ 持续出现: 可能导致看门狗超时 → 重启
```

## 4. 按问题症状的日志查找

### 症状 #1: 设备定期重启（每几小时一次）

**可能日志**:
```
... 正常日志 ...
⚠️  慢循环 #7759: 104 ms ...
⚠️⚠️ I2C 总耗时 40 ms（超过阈值）
[1秒后]
[ESP_WIFI_ERR] WiFi 看门狗超时！
[NOREBOOT] 软栈溢出...
[重启]
✅ SHT31 传感器初始化成功！
```

**诊断**: I2C 读取导致 Loop 阻塞，WiFi 看门狗 5 秒内无法完成任务，触发重启

**解决**: 
- ✅ 已通过超时保护修复
- 确保固件版本 >= v1.2

---

### 症状 #2: MQTT 数据上报中断，但设备仍在运行

**可能日志**:
```
🔍 本地采集 - 温度：24.19 °C    湿度：36.82 %RH
[等待数秒... 没有 📤 上报]
🔍 本地采集 - 温度：24.20 °C    湿度：36.83 %RH
[还是没有 📤]
```

**诊断**: WiFi 或 MQTT 连接断开，但 Loop 继续运行

**检查**:
```
1. 查看是否有 MQTT 重连日志:
   ⚠️  MQTT 发布失败...
   🟡 MQTT 连接已断开
   
2. 查看 WiFi 日志:
   ⚠️  WiFi 连接已断开
   
3. 如果都没有，可能是:
   ├─ Broker 宕机（所有设备都断）
   ├─ 网络拥塞（ACK 超时）
   └─ 防火墙阻挡（新IP被拦）
```

---

### 症状 #3: I2C 经常失败，温度/湿度不准

**可能日志**:
```
❌ I2C 读取超时...使用缓存值
🔍 本地采集 - 温度：24.19 °C    湿度：36.82 %RH  (缓存值)
📤 MQTT 上报 - 温度：24.19 °C   湿度：36.82 %RH
[5分钟后]
🔄 I2C 总线已复位（第 1 次）
[复位后恢复]
❌ I2C 读取超时...使用缓存值
```

**诊断**: I2C 总线反复故障

**检查**:
```
1. I2C 成功率:
   I2C 成功率: 85% (850/1000) ← <95%，异常！
   
2. 原因排查:
   ├─ 接线: 检查 SDA/SCL 是否有接触不良
   ├─ 干扰: 移开电源线、马达、RF 模块
   ├─ 电源: 确保电压稳定 (3.3V)
   └─ 传感器: 尝试替换 SHT31
```

## 5. 日志输出速率与诊断

### 5.1 正常速率

```
大约每 1-2 秒输出一次日志

典型模式：
- 0.0s:  采集并上报
- 0.2s:  诊断其他操作
- 30.0s: 再次采集并上报
- 30.2s: 诊断统计
```

### 5.2 异常速率

**过快** (每秒 >10 行):
```
原因: 
  ├─ Serial.printf 打印过于频繁
  ├─ DEBUG_MODE 未关闭
  └─ 错误处理逻辑进入循环
影响:
  ├─ 串口处理消耗 CPU 时间
  ├─ 可能导致 Loop 阻塞
  └─ 日志本身成为瓶颈
处理: 减少日志输出，或关闭 DEBUG_MODE
```

**过慢** (10+ 秒无日志):
```
原因:
  ├─ 设备卡住（Loop 阻塞）
  ├─ 串口缓冲区满（很少见）
  └─ 设备重启（日志丢失）
处理: 重启设备或检查硬件
```

## 6. 使用 grep 快速查找

```bash
# 查找所有错误
pio device monitor | findstr /C:"❌"

# 查找所有警告
pio device monitor | findstr /C:"⚠️"

# 查找 I2C 相关
pio device monitor | findstr /C:"I2C"

# 查找 MQTT 相关
pio device monitor | findstr /C:"MQTT"

# 查找慢循环
pio device monitor | findstr /C:"慢循环"

# 查找重启
pio device monitor | findstr /C:"初始化"

# 统计消息数（PowerShell）
$lines = @(); 
while($true) { 
  $lines += Read-Host; 
  $lines | Select-String "📤" | Measure-Object
}
```

## 7. 日志导出与分析

### 7.1 导出日志到文件

```bash
# 方法 1: 使用 PlatformIO 重定向
pio device monitor > logfile.txt

# 方法 2: 使用 tee（同时输出到屏幕和文件）
pio device monitor | tee logfile.txt

# 方法 3: 从 VS Code 中保存（复制粘贴）
# 在 PlatformIO Monitor 窗口中 Ctrl+A 全选，Ctrl+C 复制
```

### 7.2 分析日志（后期处理）

```bash
# 统计错误次数
findstr /C:"❌" logfile.txt | Measure-Object -Line

# 提取指定时间范围的日志
findstr "14:30\|14:31\|14:32" logfile.txt

# 找出最频繁的警告
findstr "⚠️" logfile.txt | Sort-Object | Uniq -c | Sort -descending
```
