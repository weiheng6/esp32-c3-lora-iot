# 🚀 Phase 2 诊断系统测试指南

## 快速开始

### 1️⃣ 上传固件

```powershell
cd f:\arduinoWorkspace\lora\platform-esp32-c3
pio run -e adafruit_qtpy_esp32c3 -t upload
```

### 2️⃣ 打开串口监视

```powershell
pio device monitor -e adafruit_qtpy_esp32c3 --baud 115200
```

### 3️⃣ 观察诊断输出

运行 2 小时，等待 30 秒汇总输出：

```
📊 30秒汇总: 平均循环时间=25 ms, 慢循环=0, I2C失败=0, MQTT失败=0
```

## 📋 测试检查清单

### 正常情况下应该看到的
- [ ] 每 30 秒输出一次汇总
- [ ] 慢循环计数 = 0（正常）
- [ ] I2C 失败 = 0
- [ ] MQTT 失败 = 0
- [ ] 温度/湿度每 30 秒采集一次
- [ ] 温度/湿度每 60 秒上报一次

### 异常情况下会看到的
- [ ] 见到 `⚠️ 慢循环` 告警（说明 LOOP > 100ms）
- [ ] 见到 `❌ I2C 读取失败` 计数
- [ ] 见到 `❌ MQTT 发送失败` 计数

## 🔍 关键观察点

### 问题 1：I2C 读取时间
```
预期看到：无 "I2C 读取耗时过长" 告警
实际如果看到：说明 I2C 读取 > 10ms，需要 Phase 3 优化
```

### 问题 2：MQTT 发送时间
```
预期看到：无 "MQTT 发送耗时" 告警
实际如果看到：说明 MQTT 发送 > 10ms，需要 Phase 3 优化
```

### 问题 3：WiFi 信号
```
预期看到：无 "WiFi 信号弱" 告警
实际如果看到：可能是设备离 AP 太远，需要移近
```

### 问题 4：慢循环频率
```
预期看到：慢循环 = 0（从不发生）
如果看到计数 > 0：说明 LOOP 时间不稳定，需要进一步调查
```

## ❌ 失败标志

如果看到：
```
⚠️ 慢循环 #5: 106 ms （I2C失败x1, MQTT失败x2）
```

那说明：还需要 Phase 3 优化（I2C 超时、MQTT 缓冲检查）

## 🛠️ 故障排除

| 问题 | 解决方案 |
|-----|--------|
| 无法上传固件 | 检查 USB 驱动、设备连接 |
| 串口输出乱码 | 检查波特率设置（应该是 115200） |
| 设备不显示温度 | 检查 SHT31 传感器连接 |
| MQTT 连接失败 | 检查 WiFi 和 MQTT 服务器配置 |
| 2 小时后冻结 | ✅ 这是我们要修复的问题，请继续进行 Phase 3 |

如果在测试中发现：

3. 其他异常现象 → 请保存串口日志供分析
