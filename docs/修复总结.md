# 🎯 MQTT 上报卡死问题修复总结

## 📌 问题概述

**现象**：系统运行正常，MQTT 上报温湿度数据，但过一段时间自动停止上报，整个系统卡死。

**已排除**：
- ✅ 网络问题（用户已确认）
- ✅ MQTT 连接问题（已加重连机制）

**根本原因**：固件层面的阻塞操作

---

## 🔍 根本原因

### **问题 1️⃣：WiFi.scanNetworks() 超级阻塞**（🔴 致命）

```cpp
// 位置：src/web_server.cpp - handleScanWiFi()
int n = WiFi.scanNetworks();  // ❌ 阻塞 10-15 秒！
```

**为什么卡死**：
- WiFi.scanNetworks() 是阻塞式调用
- 独占 WiFi 硬件 10-15 秒
- 主 loop 完全无法执行
- MQTT loop 停止，传感器采集停止
- 整个系统表现为"死机"

**触发条件**：用户在网页上点击"扫描 WiFi"按钮

---

### **问题 2️⃣：MQTT callback 耗时**（🟡 中等）

```cpp
// 位置：src/main.cpp - mqttCallback()
void mqttCallback(...) {
  // JSON 解析可能消耗时间
  // 虽然不如 scanNetworks 严重，但也会影响响应性
}
```

---

### **问题 3️⃣：loop delay 太短**（🟢 轻微）

```cpp
// 位置：src/main.cpp - loop() 末尾
delay(10);  // 太短，系统任务得不到足够时间
```

---

## ✅ 解决方案

### **修复 1：异步 WiFi 扫描**

```cpp
// 修改前（阻塞式）：
int n = WiFi.scanNetworks();

// 修改后（异步非阻塞）：
int n = WiFi.scanNetworks(true, false);  // async=true
while (WiFi.scanComplete() < 0 && maxWait-- > 0) {
  delay(10);  // 短暂等待，允许系统继续工作
}
```

**优点**：
- ✅ 不阻塞主线程
- ✅ MQTT loop 继续运行
- ✅ 传感器采集继续

---

### **修复 2：MQTT callback 性能监控**

```cpp
#if DEBUG_MODE
unsigned long callbackStart = millis();
// ... 处理逻辑 ...
unsigned long callbackDuration = millis() - callbackStart;
if (callbackDuration > 50) {
  Serial.printf("⚠️  MQTT callback 耗时：%lu ms\n", callbackDuration);
}
#endif
```

**优点**：
- ✅ 检测耗时操作
- ✅ 便于性能优化

---

### **修复 3：增加 loop delay**

```cpp
// 修改前：
delay(10);

// 修改后：
delay(20);  // 给系统任务更多时间
```

**优点**：
- ✅ 给 WiFi、蓝牙等系统任务执行时间
- ✅ 避免看门狗定时器压力
