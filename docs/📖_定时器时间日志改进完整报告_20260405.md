## 八、故障诊断

### 8.1 问题 1：看不到时间日志

**症状**：日志中不显示 `⏰ [当前时间: XX:XX:XX]`

**可能原因**：
- 日志级别设置太低（LOG_NONE 或 LOG_ERROR）
- 定时器没有启用
- 系统没有启动诊断模块

**解决方案**：
- 检查日志级别设置是否为 LOG_DEBUG
- 确保发送了启用定时器的 MQTT 命令
- 查看命令是否被正确接收（看 `🔧 ⏰ 定时控制已启用` 信息）

### 8.2 问题 2：显示的时间不对

**症状**：时间显示不正确或都是 00:00:00

**可能原因**：
- 系统时间没有通过 NTP 同步
- WiFi 连接不稳定
- 时区设置不正确

**解决方案**：
- 检查 WiFi 连接状态（查看其他日志中的连接信息）
- 等待 NTP 同步完成（通常需要几秒）
- 重启设备让时间重新同步

### 8.3 问题 3：时间段配置被接收但没有执行

**症状**：看到时间段配置信息，但继电器不动作

**可能原因**：
- 时间段没有启用（enabled = false）
- 当前时间不在配置的范围内
- 定时器总开关没有启用

**解决方案**：
- 检查日志中 `🕐 检查时间段[X]` 是否显示
- 比对日志中的当前时间和时间段范围
- 确保 `"timer": {"enabled": true}`
- 使用接近当前时间的时间段进行测试

### 8.4 问题 4：定时器启用但显示禁用

**症状**：发送启用命令后，日志显示禁用状态

**可能原因**：
- 条件控制和定时控制互斥（启用其中一个会禁用另一个）
- NVS 存储失败
- MQTT 命令格式错误

**解决方案**：
- 如果要用定时器，必须禁用条件控制（发送 `"condition": {"enabled": false}` 先）
- 如果要用条件控制，必须禁用定时器
- 检查发送的 JSON 格式是否正确
- 尝试清空配置后重新设置

### 8.5 问题 5：跨越午夜的时间段不工作

**症状**：22:00～06:00 的时间段在晚上或早上都不匹配

**可能原因**：
- 系统时间还是错误的
- 时间段的开始时间 >= 结束时间没有被正确识别为跨越午夜

**诊断方法**：
- 在晚上 23:00 检查是否匹配
- 在早上 05:00 检查是否匹配
- 查看日志中是否显示 `跨越午夜的时间段`

### 8.6 常见诊断场景表

| 现象 | 可能原因 | 解决方案 |
|------|--------|--------|
| 日志不显示时间 | 日志级别太低或系统时间未同步 | 检查日志级别，等待 NTP 同步 |
| 时间段检查不显示 | 时间段未启用或定时器未启用 | 确保 enabled 都是 true |
| 时间段范围错误 | JSON 格式有误 | 验证时间格式 "HH:MM" |
| 继电器不动作 | 当前时间不在范围内 | 用接近当前时间的范围测试 |
| 午夜时段失败 | 时间可能不准确 | 检查系统时间，观察两个时段的匹配情况 |
