# 🔍 网络连接问题诊断分析

## 问题描述

**现象：** 日志显示 "⚠️ 网络连接不可用，跳过本次上报"，但实际网络正常

**日志信息：**
```
⚠️  网络连接不可用，跳过本次上报
🔍 本地采集 - 温度：24.13 °C    湿度：32.16 %RH
⚠️  网络连接不可用，跳过本次上报
```

**关键观察：**
- LOOP 耗时诊断：21ms（正常，说明没有卡顿）
- 内存使用：24.7%（正常）
- 传感器采集：正常（温度、湿度数据准确）
- **但 MQTT 上报完全不工作**

---

## 根本原因分析

### 问题 1：`hasNetworkConnection` 标志位不更新

**代码逻辑：**
```cpp
bool hasNetworkConnection = false;  // 全局变量，初始化为 false

void checkNetworkConnection() {
  bool wifiConnected = (WiFi.status() == WL_CONNECTED);
  bool mqttConnected = mqttManager.isConnected();
  
  hasNetworkConnection = wifiConnected && mqttConnected;
  // 这里设置后...
}
```

**问题：** 这个函数被调用，但可能：
1. **WiFi 连接状态异常** - WiFi.status() 不等于 WL_CONNECTED（状态码不对）
2. **MQTT 连接问题** - mqttManager.isConnected() 返回 false
3. **检查频率不够** - 虽然 checkNetworkConnection 被调用，但连接状态可能在短时间内波动

### 问题 2：缺少详细的诊断日志

之前的代码只是简单地检查 `hasNetworkConnection`，如果是 false 就打印"网络连接不可用"，**但没有说明具体是 WiFi 还是 MQTT 的问题**。

---

## 修复方案

### 修复 1：增强网络状态诊断

**改进点：**
1. **定期输出网络状态**（每 30 秒）
   - WiFi 连接状态 + RSSI 信号强度 + 状态码
   - MQTT 连接状态
   - 综合网络状态

2. **状态变化时立即告警**
   - 网络从断开 → 连接：输出 "✅ 网络已恢复连接！"
   - 网络从连接 → 断开：输出 "❌ 网络连接断开 (WiFi: xxx, MQTT: xxx)"

**新增代码：**
```cpp
void checkNetworkConnection() {
  bool wifiConnected = (WiFi.status() == WL_CONNECTED);
  bool mqttConnected = mqttManager.isConnected();
  bool oldNetworkConnection = hasNetworkConnection;
  
  hasNetworkConnection = wifiConnected && mqttConnected;
  
  // 📊 每 30 秒输出一次网络诊断
  static unsigned long lastNetStatusLog = 0;
  if (millis() - lastNetStatusLog > 30000) {
    lastNetStatusLog = millis();
    int wifiRssi = WiFi.RSSI();
    Serial.printf("🌐 网络状态诊断:\n");
    Serial.printf("   WiFi: %s (RSSI: %d dBm, 状态码: %d)\n", 
                  wifiConnected ? "✅ 已连接" : "❌ 未连接", wifiRssi, WiFi.status());
    Serial.printf("   MQTT: %s\n", mqttConnected ? "✅ 已连接" : "❌ 未连接");
    Serial.printf("   综合: %s\n", hasNetworkConnection ? "✅ 网络可用" : "⚠️  网络不可用");
  }
  
  // ⚠️ 状态变化时立即告警
  if (oldNetworkConnection != hasNetworkConnection) {
    if (hasNetworkConnection) {
      Serial.println("✅ 网络已恢复连接！");
    } else {
      Serial.printf("❌ 网络连接断开 (WiFi: %s, MQTT: %s)\n", 
                    wifiConnected ? "✅" : "❌", mqttConnected ? "✅" : "❌");
    }
  }
}
```

**诊断输出示例：**
```
🌐 网络状态诊断:
   WiFi: ✅ 已连接 (RSSI: -48 dBm, 状态码: 3)
   MQTT: ❌ 未连接
   综合: ⚠️  网络不可用
```

### 修复 2：增强上报失败诊断

**改进点：**
1. **分层诊断上报失败原因**
   - 首先检查 hasNetworkConnection
   - 如果不可用，输出具体是 WiFi 还是 MQTT 故障
   - 缓存告警，60 秒内不重复输出

2. **详细的 MQTT 发送失败信息**
   - 输出是温度还是湿度发送失败

**新增代码：**
```cpp
void reportSensorDataToMqtt() {
  // 1. 首先检查网络连接状态
  if (!hasNetworkConnection) {
    // 📊 详细诊断为什么网络不可用
    bool wifiConnected = (WiFi.status() == WL_CONNECTED);
    bool mqttConnected = mqttManager.isConnected();
    
    static unsigned long lastNetworkFailLog = 0;
    if (millis() - lastNetworkFailLog > 60000) {  // 60 秒内最多输出一次
      lastNetworkFailLog = millis();
      Serial.printf("⚠️  网络连接不可用（WiFi:%s, MQTT:%s）\n", 
                    wifiConnected ? "✅" : "❌", mqttConnected ? "✅" : "❌");
      if (!wifiConnected) {
        Serial.printf("   → WiFi 状态码：%d (期望: %d)\n", WiFi.status(), WL_CONNECTED);
      }
      if (!mqttConnected) {
        Serial.println("   → MQTT 未连接，需要重新连接");
      }
    }
    return;
  }
  
  // 2. 其他检查...
}
```

**诊断输出示例：**
```
⚠️  网络连接不可用（WiFi:✅, MQTT:❌）
   → MQTT 未连接，需要重新连接
```

或者：
```
⚠️  网络连接不可用（WiFi:❌, MQTT:✅）
   → WiFi 状态码：1 (期望: 3)
```

## 如何使用这些诊断日志

### 1️⃣ 查找根本原因

**如果看到这个日志：**
```
🌐 网络状态诊断:
   WiFi: ✅ 已连接 (RSSI: -48 dBm, 状态码: 3)
   MQTT: ❌ 未连接
   综合: ⚠️  网络不可用
```

**说明：**
- ✅ WiFi 确实已连接（状态码 3 = WL_CONNECTED）
- ❌ **问题是 MQTT 没有连接**
- 解决方案：检查 MQTT 服务器配置、凭证、网络防火墙等

### 2️⃣ 判断网络状态是否稳定

**查看 30 秒一次的网络诊断输出：**
```
每 30 秒：
🌐 网络状态诊断: ...
```

- 如果每 30 秒都输出且状态不变 → 网络稳定
- 如果不输出 → 没有异常（正常情况，可能需要更长时间才会输出）

### 3️⃣ 追踪网络状态变化

**关键告警：**
```
❌ 网络连接断开 (WiFi: ✅, MQTT: ❌)
```

这说明网络状态从 "之前连接" 变为 "现在断开"，可以据此判断：
- 是什么时候开始断开的
- 是 WiFi 还是 MQTT 出现问题

## 🎯 后续排查步骤

如果你运行测试后看到 MQTT 未连接，检查以下内容：

### 1. MQTT 服务器配置
```cpp
// 在 mqtt_manager.cpp 中查看
mqttClient.setServer(MQTT_SERVER, MQTT_PORT);
```

### 2. 网络连接时序
- WiFi 连接需要一定时间
- MQTT 连接通常在 WiFi 之后
- 检查 MQTT 重连间隔是否过长

### 3. MQTT 心跳/保活
- MQTT 连接可能因为网络不稳定而断开
- 需要定期调用 `mqttClient.loop()` 保持心跳
