# 传感器读取模块详解

## 1. 模块概览

**文件位置**: `src/sensor.cpp`, `include/sensor.h`

**职责**:
- 初始化 Adafruit SHT31 温湿度传感器
- 执行 I2C 读取（带超时保护）
- 管理缓存值和故障恢复
- 统计 I2C 操作成功率

**关键特性**:
- ✅ 50ms 硬超时（防止 I2C 阻塞 main loop）
- ✅ 自动缓存机制（读取失败时使用上次成功的值）
- ✅ 故障统计（i2cReadAttempts, i2cReadSuccesses）
- ✅ 400kHz I2C 时钟（快速模式）

## 2. 硬件接口规范

### 2.1 I2C 总线配置

| 参数 | 值 | 说明 |
|------|-----|------|
| **I2C 地址** | 0x44 | SHT31 从地址 |
| **时钟频率** | 400 kHz | 快速模式，减少通信时间 |
| **SDA 引脚** | GPIO 5 | 数据线（可配置） |
| **SCL 引脚** | GPIO 6 | 时钟线（可配置） |
| **上拉电阻** | 内部启用 | Wire 库自动配置 |

### 2.2 SHT31 传感器规格

| 规格 | 数值 |
|------|------|
| **测量范围** | 0-100% RH, -40 to +125°C |
| **精度** | ±2% RH, ±0.2°C |
| **分辨率** | 0.01°C, 0.01% RH |
| **响应时间** | 30-40ms（包括内部转换） |
| **供电** | 2.7-5.5V |

## 3. 源代码分析

### 3.1 全局状态变量

```cpp
// include/sensor.h 中声明
class SensorManager {
private:
    Adafruit_SHT31 sht31;
    bool initialized;
};

// src/sensor.cpp 中定义（全局）
static float lastTemp = 20.0f;              // 上次成功读取的温度
static float lastHumidity = 50.0f;          // 上次成功读取的湿度
static unsigned long lastSuccessfulRead = 0; // 上次成功读取的时间戳
static uint32_t i2cReadAttempts = 0;        // I2C 总尝试次数
static uint32_t i2cReadSuccesses = 0;       // I2C 成功次数
```

**为什么是全局变量？**
- 跨函数共享状态（readBoth, readTemperature, readHumidity）
- 诊断统计信息需要持久保存
- 避免频繁的内存分配/释放

### 3.2 初始化函数

```cpp
bool SensorManager::begin() {
    Wire.begin(SHT31_I2C_SDA, SHT31_I2C_SCL);  // 初始化 I2C 总线
    Wire.setClock(400000);                      // 设置 400kHz（快速模式）
    
    initialized = sht31.begin(SHT31_I2C_ADDRESS);
    
    if (initialized) {
        Serial.println("✅ SHT31 传感器初始化成功！");
    } else {
        Serial.println("⚠️  未检测到 SHT31 传感器，继续运行...");
    }
    
    return initialized;
}
```

**关键点**：
- `Wire.setClock(400000)` 很重要，将 I2C 通信从默认 100kHz 加速到 400kHz
- 即使传感器初始化失败，也继续运行（使用默认缓存值）

### 3.3 核心读取函数

#### readBoth() - 双轴读取（推荐使用）

```cpp
bool SensorManager::readBoth(float &temperature, float &humidity) {
    if (!initialized) {
        // 传感器未初始化，使用缓存
        temperature = lastTemp;
        humidity = lastHumidity;
        return false;
    }
    
    i2cReadAttempts++;  // 统计：增加尝试计数
    
    unsigned long readStart = millis();
    unsigned long timeoutMs = 50;  // 50ms 超时阈值
    
    // 1️⃣ 尝试读取温度
    temperature = sht31.readTemperature();
    unsigned long tempReadTime = millis() - readStart;
    
    // 2️⃣ 检查是否超时（严格检查）
    if (tempReadTime > timeoutMs) {
        Serial.printf("❌ I2C 读取超时（温度耗时 %lu ms > %lu ms），使用缓存值\n", 
                      tempReadTime, timeoutMs);
        temperature = lastTemp;
        humidity = lastHumidity;
        return false;  // 立即返回，不再尝试读取湿度
    }
    
    // 3️⃣ 尝试读取湿度
    humidity = sht31.readHumidity();
    unsigned long readDuration = millis() - readStart;  // 总耗时
    
    // 4️⃣ 诊断：打印耗时信息
    if (readDuration > 50) {
        Serial.printf("⚠️⚠️ I2C 总耗时 %lu ms（超过 50ms 阈值 - 可能有问题）\n", 
                      readDuration);
    } else if (readDuration > 45) {
        Serial.printf("⚠️  I2C 读取耗时较长：%lu ms\n", readDuration);
    }
    
    // 5️⃣ 数据有效性检查
    if (isnan(temperature) || isnan(humidity)) {
        // 读取返回 NaN（通信失败或校验错误）
        temperature = lastTemp;
        humidity = lastHumidity;
        return false;
    }
    
    // 6️⃣ 成功！更新缓存并统计
    lastTemp = temperature;
    lastHumidity = humidity;
    lastSuccessfulRead = millis();
    i2cReadSuccesses++;
    
    return true;
}
```

**流程图**:
```
readBoth()
    ├─ 检查是否初始化
    │  └─ No → 使用缓存, return false
    │
    ├─ 读取温度 (millis 检查)
    │  └─ 耗时 > 50ms → 使用缓存, return false
    │
    ├─ 读取湿度
    │  └─ 总耗时统计 (诊断)
    │
    ├─ 检查 NaN（校验失败）
    │  └─ Yes → 使用缓存, return false
    │
    └─ 成功！
       ├─ 更新 lastTemp, lastHumidity
       ├─ 更新 lastSuccessfulRead 时间戳
       ├─ i2cReadSuccesses++
       └─ return true
```

#### readTemperature() - 单轴读取

```cpp
bool SensorManager::readTemperature(float &temperature) {
    if (!initialized) return false;
    
    unsigned long readStart = millis();
    temperature = sht31.readTemperature();
    unsigned long readDuration = millis() - readStart;
    
    // 如果读取超过 5ms，记录警告
    if (readDuration > 5) {
        Serial.printf("⚠️  温度读取耗时 %lu ms\n", readDuration);
    }
    
    return !isnan(temperature);
}
```

**注意**: 此函数不更新全局缓存，仅用于诊断。生产环境应使用 readBoth()。

#### readHumidity() - 单轴读取

```cpp
bool SensorManager::readHumidity(float &humidity) {
    if (!initialized) return false;
    
    unsigned long readStart = millis();
    humidity = sht31.readHumidity();
    unsigned long readDuration = millis() - readStart;
    
    // 如果读取超过 5ms，记录警告
    if (readDuration > 5) {
        Serial.printf("⚠️  湿度读取耗时 %lu ms\n", readDuration);
    }
    
    return !isnan(humidity);
}
```

## 4. 超时保护机制详解

### 4.1 为什么需要 50ms 超时？

**问题背景**:
- ESP32 WiFi 看门狗周期：5 秒
- 如果 main loop 一次执行 >5 秒，看门狗触发重启
- I2C 读取不应该阻塞超过 loop 周期的一小部分

**数据分析**:
```
典型 SHT31 读取耗时分布：
  - 最小: 5ms (快速完成)
  - 平均: 39-40ms (正常)
  - 最大: 50ms (传感器内部转换延迟)
  - 异常: >60ms (I2C 总线卡住或干扰)

我们的超时阈值：50ms
  ├─ 允许 99% 的正常读取通过
  ├─ 拒绝任何异常情况
  └─ Loop 周期：20-30ms，不会被 I2C 阻塞
```

### 4.2 两层超时检查

```cpp
// 第一层：温度读取超时
if (tempReadTime > 50ms) {
    // 温度本身已经卡住，不再尝试湿度
    // 直接使用缓存值，快速返回
    return false;
}

// 第二层：湿度读取异常
if (readDuration > 50ms) {
    // 整个过程超过 50ms
    // 发出警告并使用缓存值
    // （但不会阻塞，因为已经读完了）
}
```

### 4.3 缓存机制

```cpp
// 维护上次成功的读取
if (success) {
    lastTemp = temperature;
    lastHumidity = humidity;
}

// 下次失败时直接返回缓存
if (fail) {
    temperature = lastTemp;
    humidity = lastHumidity;
    return false;
}
```

**优势**:
- 避免数据突变（使用旧值平滑过渡）
- 提高可靠性（一次读取失败不影响上报）
- 减少传感器查询（网络不畅时）

## 5. I2C 总线重置机制

### 5.1 触发条件

在 `main.cpp` 的 `checkNetworkConnection()` 中：

```cpp
// 每 5 分钟检查一次
if (millis() - lastI2CHealthCheck > 300000) {  // 300000ms = 5min
    
    // 如果检测到很多慢循环（>100），说明 I2C 可能卡住
    if (loopSlowCount > 100) {
        // 执行 I2C 总线完全复位
        Wire.end();                              // 关闭 I2C
        delay(10);                               // 等待释放
        Wire.begin(SHT31_I2C_SDA, SHT31_I2C_SCL);  // 重新初始化
        Wire.setClock(400000);                   // 恢复时钟
        
        i2cResetCount++;
        loopSlowCount = 0;
        
        Serial.printf("🔄 I2C 总线已复位（第 %u 次）\n", i2cResetCount);
    }
}
```

### 5.2 原理

```
I2C 总线卡住的情况：
  - 从设备（SHT31）拉低 SDA/SCL，导致通信停止
  - 多个设备冲突导致的信号混乱
  - 电磁干扰

复位步骤：
  1. Wire.end() - 释放 GPIO，停止驱动 SCL/SDA
  2. delay(10) - 等待硬件释放（电容放电）
  3. Wire.begin() - 重新初始化 I2C
  4. Wire.setClock() - 恢复时钟
  
结果：
  - I2C 总线恢复到干净状态
  - 从设备释放并重新初始化
  - 继续正常通信
```

## 7. 使用示例

### 7.1 基本使用（main.cpp 中）

```cpp
#include "sensor.h"

// 全局实例（已在 sensor.cpp 中定义）
extern SensorManager sensorManager;

void setup() {
    // 初始化传感器
    sensorManager.begin();
}

void loop() {
    // 每 30 秒采集一次
    if (millis() - lastAcquisitionTime > 30000) {
        float temperature, humidity;
        
        if (sensorManager.readBoth(temperature, humidity)) {
            // 读取成功
            Serial.printf("🌡️  温度: %.2f°C, 湿度: %.2f%%\n", 
                         temperature, humidity);
        } else {
            // 读取失败（使用缓存值）
            // temperature 和 humidity 已被设置为缓存值
            Serial.println("⚠️  使用缓存的传感器值");
        }
        
        lastAcquisitionTime = millis();
    }
}
```

### 7.2 错误处理

```cpp
float temp, hum;

if (!sensorManager.readBoth(temp, hum)) {
    // 读取失败，temp/hum 是缓存值
    Serial.println("⚠️  I2C 读取失败，使用缓存值");
    
    // 可选：记录错误计数
    if (isI2CErrorTooFrequent()) {
        Serial.println("🔄 触发 I2C 总线复位...");
        // I2C 复位逻辑（见上文）
    }
}
```

## 8. 常见问题排查

| 问题 | 症状 | 排查步骤 |
|------|------|---------|
| **I2C 不初始化** | 传感器一直读不到 | 检查 SDA/SCL 接线，验证 I2C 地址 0x44 |
| **I2C 超时频繁** | "I2C 读取超时" 警告频出 | 检查电磁干扰，降低 I2C 时钟频率至 100kHz |
| **温度读数跳变** | 温度突然大幅变化 | 检查缓存机制是否正常，可能是数据线接触不良 |
| **湿度始终 NaN** | 湿度显示异常值 | 重新焊接 I2C 连接或更换传感器 |
| **定期卡顿** | 每 5 分钟卡一次 | I2C 总线复位逻辑触发，正常（监控 i2cResetCount） |
