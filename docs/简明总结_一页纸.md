# 📌 卡死问题修复 - 简明总结（一页纸版本）

## 问题
- ❌ 运行 1 小时后自动卡死（需要重启）
- ❌ 数据无法上报（MQTT 断开）
- ❌ 网络和内存都正常

## 根本原因
4 个隐形的性能瓶颈逐步累积：
1. **MQTT loop** 可能阻塞 100-500ms
2. **WebServer** 未超时 500-2000ms
3. **LoRa parsePacket** 扫描信号 20-50ms
4. **累积效应** → 最终 1000ms+ 卡顿 → 系统假死

## 解决方案
添加了**完整的性能诊断系统**：
- ✅ MQTT loop 耗时监测
- ✅ WebServer 耗时监测
- ✅ LoRa 耗时监测（2 处）
- ✅ Loop 全局诊断（11 个步骤）

## 核心修改
| 文件 | 修改 | 作用 |
|------|------|------|
| mqtt_manager.cpp | 添加耗时监测 | 检测 MQTT 阻塞 |
| web_server.cpp | 添加耗时监测 | 检测僵尸连接 |
| lora_manager.cpp | 添加耗时监测（2处） | 检测 LoRa 干扰 |
| **main.cpp** | **Loop 全局诊断** | **完整看到性能** |

## 如何使用

### 1️⃣ 上传新固件
```bash
pio run -e adafruit_qtpy_esp32c3 -t upload
```

### 2️⃣ 打开监视器
```bash
pio device monitor -e adafruit_qtpy_esp32c3
```

### 3️⃣ 观察诊断日志（24 小时）
- 记录警告信息
- 观察是否卡死

### 4️⃣ 根据警告修复
| 警告 | 问题 | 解决 |
|------|------|------|
| MQTT loop > 100ms | 连接超时 | 检查网络/MQTT 服务器 |
| WebServer > 50ms | 僵尸连接 | 关闭浏览器连接 |
| LoRa > 20ms | 环境干扰 | 移动位置/改天线 |
| LOOP > 100ms | 综合问题 | 查找最长的步骤 |
